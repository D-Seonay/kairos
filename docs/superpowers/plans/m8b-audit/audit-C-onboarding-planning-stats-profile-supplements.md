# Audit accessibilité C (lecture seule) : Onboarding, Planning, Stats, Profil, Compléments

Chemins relatifs à `Packages/PulseFeatures/Sources/`. Rien n'a été modifié, construit ni lancé.
Composants du design system lus pour éviter les faux positifs : `RecoveryGauge` (étiquette OK, reduceMotion OK), `AuraBackground` (masqué, reduceMotion OK), `StepProgressBar` (étiquette OK), `FocusSlider` (étiquette + valeur OK), `WeekdayToggleRow` (étiquette + valeur + cible 44 OK), `PillButtonStyle` (cible 44 OK), `PulseSectionHeader` (en-tête + ViewThatFits OK), `PulseRow`, `IconChip` (masqué OK), `ChoicePills` (trait sélectionné OK).

Déjà traité, non rapporté : tuiles Stats et Profil (une phrase, grille à 1 colonne en `isAccessibilitySize`), résumés des graphiques en étiquette, `MonthDayCell` (`MonthModel.accessibilityText`), `WeekStrip` (étiquette), `WeekDayRow` (actions nommées Déplacer / Garder), pastilles de rang masquées, `OnboardingOptionCard` et `ProgramTemplateCard` (`.isSelected`), `WeekPreviewRow` (`ProgramWeekPreview.accessibilityLabel`), animation de `OnboardingFlowView` (reduceMotion), `StatsViewSegment` (`.isSelected`), barres stock / régularité (étiquette + valeur), bouton retour de l'onboarding (44 pt + étiquette).

Constats transverses :
- Aucune annonce VoiceOver (`AccessibilityNotification.Announcement`) dans ces cinq modules.
- Aucun graphique n'a de `accessibilityChartDescriptor` : tous passent par `.accessibilityElement(children: .ignore)` + étiquette, ce qui supprime le graphique audio automatique de Swift Charts.
- Aucun aperçu à `accessibility3` (voir « Aperçus » en bas).
- Les textes composés sont aujourd'hui des propriétés privées des vues (`summary`, `accessibilityText`, `mapLabel`...) : à sortir vers `StatsText`, `ProfileText`, `PlanningText`, `OnboardingCopy`, `SupplementLabels` pour les tester.
